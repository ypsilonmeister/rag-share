# rag-share

複数のAIアシスタントで1つの長期記憶（Google Driveのフォルダ）を共有するための、
**読み取り専用MCP検索サーバー**です。

新しいメモリは、各AIが自分のDriveアクセスでフォルダへ直接書きます。このサーバーの
役割は検索と本文の読み取りで、MCPツールは `memory_search` と `memory_read` です。認証はBearerトークン、
または静的トークンを使えないクライアント（ChatGPTのMCPコネクタなど）のために
内蔵したOAuth 2.0認可サーバーで行います。

English: [README.md](README.md)

`memory_search {query, k}` の結果の `fileId` を使い、
`memory_read {file_id, offset: 0, limit: 4000}` で索引内の本文を読みます。
`next_offset` が null になるまで続けると全文を取得できます。
位置・上限はUnicode文字数で、1回の上限は8,000文字です。
途中で `modifiedTime` が変わったら最初から読み直してください。
検索と同じ認証が必要で、索引にないIDやファイルパスは指定できません。

## 仕組み

```
Google Driveフォルダ ── pull.py（サービスアカウント、約30分ごと）
        │                 テキストを抽出し corpus/<fileId>.txt
        ▼                 と corpus/manifest.json を書く
   corpus/ ── server.py が manifest.json を60秒ごとに確認し、
        │      変わったファイルだけ再チャンク・再埋め込み
        ▼
   MCPクライアント ── memory_search {query, k} ──► ハイブリッド検索
                  （多言語埋め込みのコサイン 0.4 + 文字bigram BM25 0.6、
                    ファイル単位で重複除去）
```

- **読み取り専用**: サーバーに書き込み経路そのものがありません。保存は
  Drive経由のみで、MCP経由では行いません。
- **認証は2種類**: 静的トークン（`tokens.json` にはSHA-256ハッシュだけを保存）と、
  内蔵OAuth 2.0（動的クライアント登録、認可コード＋PKCE S256、リフレッシュ
  トークンのローテーション、保存はハッシュのみ）。承認画面は所有者の「合言葉」で
  守られ、合言葉ファイルがない間は全ての承認を拒否します（fail closed）。
- **アクセスログ**: 呼び出しごとにTSV 1行（時刻、トークンのラベル、ツール、
  クエリ先頭200文字、ヒット数）。秘密情報は記録しません。

## 必要なもの

- Python 3.11以上（開発は3.14）
- ミラーするGoogle Driveフォルダ
- 取得用にGoogle Cloudの**サービスアカウント**（フォルダを「閲覧者」で共有し、
  そのプロジェクトでDrive APIを有効化）
- 実行時メモリ 約1.5GB（大半は埋め込みモデルです。索引自体は個人規模では
  ごく小さいです）

## セットアップ

一番簡単なのはDockerです。

```sh
git clone <this repo> rag-share && cd rag-share
cp rag-share.env.example rag-share.env   # 値を編集
docker compose up -d --build
docker compose exec server cat /data/INITIAL_TOKEN.txt   # 初期トークン
```

実行時の状態はすべて `rag-share-data` ボリューム（コンテナ内の `/data`）に
入ります。取得は `docker compose run --rm pull` で1回ずつ実行する形です。

Pythonで直接動かす場合は次のとおりです（systemdの例も `systemd/` にあります）。

```sh
git clone <this repo> rag-share && cd rag-share
python3 -m venv venv
venv/bin/pip install -r requirements.txt
cp rag-share.env.example rag-share.env   # 値を編集
set -a && . ./rag-share.env && set +a
venv/bin/python server.py
```

初回起動時に初期トークンが生成され、ハッシュが `tokens.json`、平文は所有者向けに
`INITIAL_TOKEN.txt`（0600）だけへ書かれます。

取得（pull.py）は、サービスアカウントの鍵JSONを `sa-key.json` として配置し
（0600、**コミット厳禁**）、`RAG_SHARE_FOLDER_ID` を設定して実行します。
空の一覧を受け取った場合はフォルダ自体へのアクセスを確認し、確認できない場合は
既存コーパスを守るため中断します。アクセス可能な空フォルダなら最後の記憶の削除も
反映します。一時的な取得失敗では直近の正常な版を保持し、次回に再試行します。
定期実行には `systemd/` のタイマーが使えます。

OAuthクライアントを使う場合は、`consent-passphrase.txt` に合言葉を1行で置き
（0600）、`RAG_SHARE_PUBLIC_BASE` に公開側のHTTPSオリジンを設定して、
Tailscale Funnelやリバースプロキシで公開します。

## AIに使わせるためのプロンプト

サーバーだけではAIは参加しません。仕組みを完成させる2つのプロンプトが
`docs/` にあります。

1. **書き出しガイド**（`docs/MEMORY_WRITING_GUIDE.ja.md`、[English](docs/MEMORY_WRITING_GUIDE.md)）:
   各AIがメモリを保存するときの規約（ファイル名、メタ情報、事実と解釈の分離、
   書いてはいけないもの）。コピーを**共有フォルダの中自体**にも置くと、
   検索で常に最新の規約を参照できます。各AIのカスタム指示などにも渡してください。
2. **参加プロンプト**（`docs/BOOTSTRAP_PROMPT.ja.md`、[English](docs/BOOTSTRAP_PROMPT.md)）:
   新しいAIに**1回だけ**貼るものです。書き出しガイドを検索で取り込ませ、
   要点をそのAIの保持の仕組みに保存させます。

フォルダ名はご自身の環境に合わせて読み替えてください。

## セキュリティ上の注意（公開前に必読）

OAuth状態は権限を制限した一時ファイルへ書き込み、flush/fsync後に置き換えます。
既存JSONの破損は空の状態として扱わずエラーにします。正常なバックアップを復元してから
再試行してください。バックアップも秘密情報として管理してください。未作成の状態は初期化できます。

- OAuth認可サーバーは**学習用の自前実装**です。RFCの形（9728/8414メタデータ、
  PKCE S256、単回コード、リフレッシュのローテーション、ハッシュ保存）には
  沿っていますが、監査を受けたものではありません。個人利用の範囲を超える
  用途では、実績のある認可サーバーを検討してください。
- 合言葉は**単一の共有秘密**です。知った人は自分のクライアントを承認して
  あなたのメモリを検索できます。強い合言葉を使い、必要ならネットワーク側の
  制限も併用してください。
- 検索結果はメモリフォルダの**中身そのもの**をトークン保持者に開示します。
  トークンの配布は慎重に。取り消しは `tokens.json` からラベルを消すだけで
  即時反映されます。
- 実運用中のエンドポイントURLを、このコードと一緒に公開しないでください。

## 設計メモ

- **なぜメモリ内索引か**: 個人規模（数十〜数百件のノート）では索引は小さく、
  メモリを食うのは索引ではなくモデル本体です。埋め込みの永続化（SQLite等）が
  効いてくるのは、再起動時の全再計算が数分かかる規模（目安: ファイル1,000件、
  テキスト10MB、チャンク1万個あたり）からです。
- **なぜファイル単位の重複除去か**: 同じ話題のファイルが複数あると、上位結果が
  1ファイルの似たチャンクで埋まるためです。
- **なぜ取得にサービスアカウントか**: 所有者のOAuthトークンをサーバー機に
  置かず、アクセス範囲を1フォルダの読み取りだけに絞れるためです。
